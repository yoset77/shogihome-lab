# Server-owned Analysis Jobs

## Intent and Scope

棋譜解析をBrowserのtimerや接続寿命から分離し、Browserを閉じても解析を完了できるようにします。接続の復旧と解析のやり直しを同じ操作にしません。

対象はWrapperに登録されたresearch対応LAN engineです。通常検討・詰み探索の移行、native USI、解析時の外部定跡探索、Server再起動からの復旧、共同編集、複数画面からの同時アタッチ、単一棋譜解析のファイルへの自動保存は対象外です。通常対局の移譲は [Game Sessions](game-sessions.md) として別に扱います。

## Fixed Work, Independent Browsing

入力と選択経路は開始時に固定し、解析中の操作で対象を変更しません。アタッチ中は文書の編集と閲覧を受け付けず、盤面は解析の進行に追従します。閲覧が必要な場合はデタッチしてから行い、必要に応じて再アタッチします。解析中の閲覧と追従の停止・再開を両立させると状態が増えるため、この単純さを優先しています。

MultiPVはジョブ単位の指定とし、エンジンの登録設定や通常検討の条件を変更しません。LANの通常検討と同じく指定命令を送信しますが、エンジン固有の対応可否や採用値の確認は行いません。棋譜注釈・悪手判定は第1候補を使い、複数候補の参照には既存のAnalysis DBを使用します。DBは候補順位ごとの深い結果を優先する蓄積であり、今回の探索一式のsnapshotではありません。

## Batch Analysis

連続棋譜解析は、フォルダまたは実行済み検索の全一致棋譜をServerで処理します。既定は直列で、並列実行は棋譜ファイル単位です。隣接局面の評価比較を保つため、棋譜内の局面は並列化しません。形式を選び分けるユースケースは想定せず、対応する棋譜形式をすべて対象にします。検索条件は棋譜選択にだけ使い、解析経路は本譜に限定します。確認した対象一覧は保存に伴うindex更新や新しいファイル追加で変化させず、棋譜内容は各ファイルの処理開始時に固定します。

保存と解析済みスキップは本家の連続解析に合わせます。完了した棋譜は元ファイルへ上書きし、解析途中の取消では保存しません。スキップは変化を含む指し手コメントの解析情報の有無で判断する粗い判定で、部分解析やエンジン・MultiPV・解析条件の違いは考慮しません。DBは棋譜単位の完了判定には使いません。コメント出力なしでは新しい解析済みマーカーは作られません。

上書きの明示確認と事前バックアップの案内を行い、公開前に原本変更を検出した場合は保存を拒否します。外部writerとの完全な同時編集排他や元の表記のバイト単位の保持、自動バックアップ、別名保存は保証しません。読込・保存失敗は次へ進み、engine異常はバッチを止めます。保存開始後の取消は保存結果の確定を待ち、保存済み棋譜を巻き戻しません。

バッチ全体を1ジョブとして扱い、単一解析と同じ実行枠を占有します。workerごとにエンジンを再利用しますが、棋譜境界で評価比較を切り離します。独立バッチの多重起動や資源待ちは導入しません。

並列実行はバックグラウンド専用とし、進捗・停止をJobsDialogに集約します。複数の処理中棋譜から盤面追従先を選択する機構や、未保存の途中結果を回収するUIは設けません。保存済み棋譜は既存の詳細画面から元ファイルを開きます。並列数はCPUやメモリの余裕を保証しないため、エンジンのThreads・Hash設定を考慮する必要があります。CPU予算は既存の[リソース予算](resource-budget.md)を使い、並列数に合わせたThreadsの自動変更は行いません。

直列実行では従来どおりアタッチと局面追従を許可します。画面追従を外してもServerの解析・保存は継続します。過去の全棋譜snapshotをメモリへ蓄積せず、直列では処理中または最後に解析した棋譜だけを保持し、並列では処理完了した棋譜を保持しません。

バッチ全体には棋譜単位より長い独立した期限を設け、大量棋譜の処理を許容しつつ実行枠の無期限占有を防ぎます。この期限は安全上限であり、全対象の完走を保証するものではありません。

実行・原本保護・通信境界は [batch tests](../../shogihome/src/tests/server/batch_analysis.spec.ts) と [parallel batch tests](../../shogihome/src/tests/server/parallel_batch_analysis.spec.ts)、TCP/DB経路は [integration tests](../../shogihome/src/tests/server/analysis_job_integration.spec.ts)、画面追従と未保存保護は [renderer tests](../../shogihome/src/tests/renderer/store/analysis.spec.ts) を参照してください。

## Cancellation and Recovery

- 通信断は同期の中断であって取消ではありません。失効したjobを自動再実行せず、復元不能と新規解析を区別します。
- 取消・失敗でも有効な途中結果は残します。ただし、取消後の出力や不完全な比較から新しい注釈を作りません。
- 復元時は解析結果より現在の未保存棋譜の保護を優先します。別内容への置き換えは確認とbackupを伴い、復元を断ってもjobそのものは取り消しません。
- ジョブ一覧を、別端末や復帰情報のない画面からの発見・結果回収の基本導線とします。同じタブのreloadは安全な場合だけ自動復帰し、デタッチ済みの画面や旧所有者からの自動移譲は行いません。

## Attachment Is Not Execution

デタッチは解析を止める操作ではなく、画面と文書の同期を外す操作です。これにより解析中も別の棋譜を編集できます。バックグラウンドで完了した結果を回収できるよう、一覧は進行中だけでなく保持期間内の完了・取消・失敗も扱います。

同時アタッチを一画面に制限することで、共同編集や複数の操作権を導入せず端末間の引き継ぎを提供します。タブの復帰意図と永続的な未確認要求の台帳を分け、古い台帳が存在するだけで画面や操作権を取り返さないようにします。

## Synchronization Budget

HTTP同期間隔は共有rate limitを使い切らず、他の操作の余裕を残すことを判断基準とします。通常間隔を守っていても他の通信と制限を共有するため、rate limit時の待機・再試行は必要です。待機を解析失敗や取消の完了とみなしません。

## Persistence Boundary

結果同期は棋譜への注釈反映であり、ファイル保存ではありません。単一解析や未保存の途中結果の保存はユーザーの明示操作に残し、連続解析の完了棋譜の保存はServerが別に所有します。完了結果と復元用識別子を同時に失わないよう、Browserの通常の棋譜復元情報へ反映できるまでjobとのlinkageを残します。

責務、実行寿命、同期・復元の契約は [Analysis Job Architecture](../architecture/analysis-jobs.md) を参照してください。
