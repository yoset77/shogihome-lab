# Server-owned Analysis Jobs

## Intent and Scope

棋譜解析をBrowserのtimerや接続寿命から分離し、Browserを閉じても解析を完了できるようにします。接続の復旧と解析のやり直しを同じ操作にしません。

対象はWrapperに登録されたresearch対応LAN engineです。通常検討・詰み探索の移行、native USI、解析時の外部定跡探索、Server再起動からの復旧、共同編集、別端末への制御移譲、解析棋譜ファイルへの自動保存は対象外です。通常対局の移譲は [Game Sessions](game-sessions.md) として別に扱います。

## Fixed Work, Independent Browsing

入力と選択経路は開始時に固定し、解析中の閲覧で対象を変更しません。解析cursorと閲覧cursorを分離することで、ユーザーが別の分岐を確認しても同じ仕事を継続できます。文書編集は制限しますが、閲覧まで止めることはしません。

手動閲覧後は自動追従を止め、解析の進行よりユーザーの閲覧位置を優先します。

## Cancellation and Recovery

- 通信断は同期の中断であって取消ではありません。失効したjobを自動再実行せず、復元不能と新規解析を区別します。
- 取消・失敗でも有効な途中結果は残します。ただし、取消後の出力や不完全な比較から新しい注釈を作りません。
- 復元時は解析結果より現在の未保存棋譜の保護を優先します。別内容への置き換えは確認とbackupを伴い、復元を断ってもjobそのものは取り消しません。
- Reloadでの自動復元を断った場合も、通常の解析操作から再度復元できるようにし、専用の復元管理UIは増やしません。

## Synchronization Budget

HTTP同期間隔は共有rate limitを使い切らず、他の操作の余裕を残すことを判断基準とします。通常間隔を守っていても他の通信と制限を共有するため、rate limit時の待機・再試行は必要です。待機を解析失敗や取消の完了とみなしません。

## Persistence Boundary

結果同期は棋譜への注釈反映であり、ファイル保存ではありません。保存は従来どおりユーザーの明示操作に残します。完了結果と復元用識別子を同時に失わないよう、Browserの通常の棋譜復元情報へ反映できるまでjobとのlinkageを残します。

責務、実行寿命、同期・復元の契約は [Analysis Job Architecture](../architecture/analysis-jobs.md) を参照してください。
