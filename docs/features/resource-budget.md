# Engine Resource Budget

この文書は、エンジンの同時実行をグループ予算（リソース予算）で制限する機能の意図、判断理由、対象外を説明します。実装と schema は `shogihome/src/common/engine/relay_protocol.ts`、`shogihome/src/server/engine/resources.ts`、テストを正本とします。

## Purpose and Intent

主目的は、ユーザーのミスによる セルフDDoS（同一マシンでの過剰なエンジン同時実行）の防止です。実測制御ではなく、設定値から見積もった消費量で新規起動を拒否する、緩く best-effort な仕組みとして設計しています。厳密な資源保証は目標ではありません。

## Design Rationale

- **Cost model**: CPU 消費量は `Threads` オプションだけから見積もる。解決不能な場合のフォールバックは 1 とし、誤って緩めに見積もっても障害にはならない（手動設定を GUI で促す）。`USI_Hash` からのメモリ推定、GPU/VRAM の自動見積もりは最初の対象外。
- **Default off**: 既存の利用を拒否したくないため、機能は明示的に有効化する。保存済み設定は移行や自動変更をしない。
- **Owner-scoped reservation**: 予約は「実行の所有者」単位で行い、開始から終了収束まで保持する。対局は AI 同士が交互に探索する（ponder 非対応）前提で、グループごとの両エンジン消費量の最大値を 1 予約として扱う。将来的にメモリや VRAM を対象にする場合は両プロセスの保持量が同時存在するため、この最大値方式をそのまま再利用しない。
- **Atomic acquire**: 上限判定と予約は同一の同期処理で行い、同時要求による超過を作らない。待ち行列や自動再試行は導入しない。
- **Startup snapshot**: relay は Browser の一覧取得やキャッシュに依存せず、起動前に設定を取得する。対局・解析は取得した設定を固定し、同じ snapshot から予約と内部エンジン起動を行う。Wrapper が `run` 時に再読込する設定との厳密な世代照合は保証しない。
- **Accounting and enforcement**: 制限が無効でも、所属グループが解決できるエンジンの予約量を記録する。有効化は既存の予約量を含めた新規受付に適用し、稼働中のエンジンを停止しない。削除されたグループも予約が残る間は計上を保持し、同じ ID の再登録で引き継ぐ。
- **Best-effort release**: 強制切断と wrapper プロセス回収の間に生じる一時的な超過や、複数 Middle Server / アプリ外プロセスとの合算は保証対象外とする。予約の解放は冪等とし、削除済みグループは最後の予約の解放後に回収する。
- **Registry format**: `engines.json` を v2 オブジェクト（`resources` + `engines`）に拡張しつつ、旧配列ルートの読み込みを維持する。編集後にリソース設定が空で無効の間は配列ルートへ書き戻し、エンジン側ツールのみを配布した既存環境との互換を優先する。

## Non-goals

- CPU 使用率の実測や OS レベルの制限（cgroups、Job Objects による CPU クランプ）
- ponder 対応（未対応であり、対局中は交互探索を前提とする）
- 実行優先度・スケジューリング、リソース待ち行列
- リモートホストの容量の自動検出（予算は手動設定）
