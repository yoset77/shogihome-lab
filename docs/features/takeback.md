# 人間対AIの「待った」

## 目的と対象

練習対局で、人間が最後に指した手を指し直せるようにします。人間対LANエンジン・内蔵AIを対象とし、人間同士・AI同士・終局後は対象外です。LANでは識別付き探索と取消snapshotに対応するserverが必要です。

## 操作と復元範囲

- 人間の直前の着手前へ戻します。AI思考中は1手、応手後は2手です。
- 人間がまだ着手していなければ利用できません。繰り返し利用できますが、今回の対局開始局面より前には戻しません。
- 双方の時計を戻り先の手番開始時点へ復元します。取り消した手による加算も取り消し、秒読みを復元します。取消・再接続待ち時間は課金しません。
- 今回の対局で追加した取り消し対象の棋譜ノードとコメント・時間・評価情報を削除します。途中局面からの開始時に既存ノードを再利用していた場合は、そのノードを削除せず元の注釈・時間・評価情報を復元し、既存の分岐を保護します。
- 操作中は棋譜をそのまま表示し、時計・盤面入力・投了・勝ち宣言・重複する待ったを無効化します。対局中断は引き続き利用できます。
- デスクトップの対局操作欄とモバイルのメニューに「待った」を表示します。操作可否は `GameManager` が決定します。デスクトップの対局操作欄は5ボタン以内とし、勝ち宣言・持将棋の点数・戦績確認は「その他」メニューから操作します。

## 確定手順

`GameManager` は各手番開始時に棋譜checkpointと双方の時計を保存します。受付時に時計の経過を確定し、時間切れが成立していれば終局を優先します。

1. 戻り先を確定し、`TAKING_BACK` に遷移する。
2. 旧イベントIDを失効し、双方の時計とPlayer入力を停止する。
3. Playerの `cancelSearch()` を実行する。通常の `stop()` は結果を利用する用途として残す。
4. LANでは、serverの取消完了境界を確認する。定跡検索はローカルで即時失効させ、応答待ちが探索ロックを保持し続けないようにする。
5. 操作がまだ有効なら `RecordManager` で棋譜と時計をまとめて復元し、整合した状態から変更通知・バックアップ更新を行う。
6. 人間の手番を再開する。

取消開始前に届いた着手は通常どおり確定します。開始後の着手・投了・評価値・エラーは旧操作として無視します。確認ダイアログの投了・勝ち宣言にもイベントIDを適用し、待った前の確認操作を新しい手番へ適用しません。

## 通信障害

探索は局面文字列だけでなくsession実体IDと探索IDで照合します。同じ手を指し直しても旧出力を採用しません。取消は「指定探索ID以下を無効化」という再送可能な要求です。詳細は [Remote Engine Architecture](../architecture/remote-engine.md) と共有relay codecを正本とします。

一時切断では時計を停止したまま再同期します。送信済みの取消完了通知が届かなかった場合も、serverの最新snapshotから完了を確認できます。再接続前の古い探索要求を無条件に再送しません。

停止無応答、session失効、server再起動、取消の待機期限超過では、巻き戻しを確定せず元の進行を保持して対局中断します。Browser側の取消待機にはserverが公開した保護期間と停止応答の猶予を合わせた上限を設けます。ユーザーが先に中断した場合、後から届く取消完了で対局を再開しません。

checkpointはメモリー上の状態であり、ページ再読み込み後の対局再開には利用しません。
