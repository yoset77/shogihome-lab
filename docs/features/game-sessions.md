# 対局セッションの設計意図

## 目的と対象範囲

通常のWeb対局をMiddle Server上で実行し、Browserを閉じてもAI同士の対局・連続対局・保存が終了しないようにします。Browserは交換可能な操作UIであり、別の対局executorではありません。

ShogiHome Labは外部で設定したUSIエンジンの利用者を対象とします。別のエンジン実行モデルを導入する代わりに、上流版の初心者向け・ランダムの内蔵プレイヤーは廃止します。旧設定は既存の棋譜を書き換えずに移行します。Native USI、ponder、Server再起動からの復旧は対象外です。通常検討・詰み探索は、この移譲に含めません。

## 切断時の方針

切断を対局の進行を取り消す指示とはみなしません。AI手番は完了させ、人間手番はServerが操作用Browserの切断を検知した時点で停止します。既に計上した消費時間は遡って戻さず、停止前に成立した時間切れを優先します。Browserの通信遅延や再接続のタイミングを対局ルールに持ち込まず、Serverの時計を正本に保つためです。

再接続は既存の対局を復元する操作です。Session失効やServer再起動を理由に、別の対局を暗黙に開始しません。復元時も、Browserで開いている別の未保存棋譜を保護します。

AI同士の対局にはバックグラウンド開始とデタッチを提供し、Serverのジョブ一覧から同じServerに接続する別端末へ引き継げます。同時アタッチは一画面とし、既存の画面からの移譲は明示確認を必要とします。人間参加対局のデタッチや複数画面からの同時操作は対象外です。

並列連続対局はエンジン同士のバックグラウンド実行に限定します。複数の進行中棋譜から追従先を選ぶUIやworker別のアタッチは設けず、進捗・戦績・停止はJobsDialogに集約します。直列対局の盤面追従や人間参加対局は従来どおりです。開始時のプレイヤーを戦績の基準にし、同名エンジンや先後交代でも集計先を混同しません。

並列数は独立した対局workerの数であり、同時に実行できる別sessionを増やす設定ではありません。既存の[CPU予算](resource-budget.md)は合計しますが、RAM・VRAMの余裕は保証せず、Threadsの自動調整も行いません。Hashなどの設定も含め、利用環境に合わせて並列数を選ぶ必要があります。

同じタブのreloadではsessionStorageの復帰意図を照合し、安全な場合は確認なしで復帰します。localStorageの未確認要求台帳はジョブの発見や自動アタッチの根拠にはしません。明示的なデタッチを尊重し、旧画面の再接続で操作権が戻ることを防ぐためです。

切断された人間手番を無期限には保持しません。Browser storageの削除などで復元用識別子を失っても、対局枠とエンジンを永久に占有しないため、切断期間が期限を超えた停止中対局は中断します。AI手番の完了とAI同士の無接続継続は妨げません。

## 既存の棋譜保存層を再利用する理由

履歴は最近の棋譜を復元するための補助であり、全対局を保管するarchiveではありません。すべての対局を残したい場合は自動保存を使います。自動保存なし・保存失敗時の棋譜は既存の履歴backupを利用し、第3の保存層や独立した未保存棋譜の容量制限、保存再試行UIは導入しません。

並列対局の保存済み棋譜はジョブの詳細から開きます。workerの最後の棋譜や未保存snapshotを結果の代替にしません。履歴は有界なので、自動保存なしの大量対局で全棋譜の回収は保証しません。

保存・履歴登録の失敗は通知しますが、連続対局の次局への進行は妨げません。終局棋譜のファイル・履歴は既存の永続化層を使い、稼働中sessionの保持を棋譜保存の代わりにはしません。

個人利用を前提とし、Launcher／Serverの停止前に対局を終える運用を想定します。終了時の中断棋譜保存を保証するためのServer全体の保存完了待ちや、Launcherからの専用終了通知は導入しません。

責務、実行寿命、同期、時計の保証は [対局セッションの設計](../architecture/game-sessions.md)、巻き戻し範囲の判断理由は [待った](takeback.md) を参照してください。
