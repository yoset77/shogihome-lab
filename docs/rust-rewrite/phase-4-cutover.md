# Phase 4 — Cutover and Release Packaging

Release packaging moves from the embedded-Python/Tk/C# chain to the
Tauri launcher + Rust wrapper. The TCP line protocol is unchanged, so the
Middle Server needs no rewiring.

## 1. Release layout (portable ZIP)

```text
shogihome-lab-vX.Y.Z/
├── ShogiHomeLab.exe        # Tauri launcher (`tauri build --no-bundle`)
├── wrapper.exe             # `shogihome-wrapper` release build, renamed
├── icon.png / README.txt
├── shogihome/              # dist/bin/* + docs/webapp + .env (unchanged)
└── engine-wrapper/
    ├── engines.json / .env # seeds (unchanged names)
    ├── VERSION              # tag-derived, read by update.rs
    └── licenses/
        ├── RUST-THIRD-PARTY-NOTICES.txt  # cargo-about (workspace + shell)
        └── UI-THIRD-PARTY.json           # license-checker (launcher UI)
```

Split-host layout (same build outputs, no server bundle):

```text
shogihome-lab-engine-tools-vX.Y.Z/
├── ShogiHomeLab.exe        # same binary; run with --config-editor
├── wrapper.exe             # same binary; run with --config-dir DIR
├── ConfigEditor.cmd        # editor-only entry point (no services)
├── icon.png / README.txt   # dedicated engine-tools guide
└── engine-wrapper/
    ├── engines.json        # seed
    ├── .env                # seed (wrapper autoloads <config-dir>/.env)
    ├── VERSION
    └── licenses/
```

`ConfigEditor.cmd` launches
`ShogiHomeLab.exe --config-editor --config-dir "<cmd-dir>\engine-wrapper"`.
The wrapper side reads `<config-dir>/.env` automatically
(precedence: CLI > environment > `.env` > defaults; `${VAR}` is literal).
The launcher still owns its resolved snapshot and passes `--no-env-file`
to the supervised wrapper so readiness and runtime cannot drift.

Dropped from the package: embedded Python, `launcher.py`,
`engine_wrapper.py`, `config_editor.py`, `config_editor.html`, `common.py`,
`i18n.py`, `server_settings.py`, `update_checker.py`, the C# shim. The
sources stay in the repo as fallback (see §7).

## 2. Decisions

- **Version authority** (`scripts/check_versions.py`, stdlib only):
  `pyproject.toml`, `shogihome/package.json`, workspace
  `[workspace.package]`, `launcher-app/package.json`, `tauri.conf.json`
  must agree; both crates must use `version.workspace`. CI checks the
  five sources on every push; release checks them plus `--tag` before
  building (closes `phase-0-baseline.md` §1).
- **`externalBin` removed**: the backend spawns `wrapper.exe` next to the
  launcher exe with an explicit path (`main.rs::service_specs`). A Tauri
  sidecar rename (`wrapper-<triple>.exe`) would not match, and the shell
  plugin offers no suspended spawn for Job-Object assignment.
- **`webviewInstallMode` removed**: installer-only feature, meaningless
  for portable ZIP. Distribution relies on preinstalled WebView2 plus the
  startup guidance (`phase-0-poc.md` §4); clean-VM check stays manual (§8).
- **`tauri build --no-bundle`**: the ZIP is assembled by `release.yml`
  from the raw exes; `tauri build` with bundling is for local installer
  experiments only.
- **`mainBinaryName: ShogiHomeLab`** explicitly names the portable executable;
  `productName` alone does not rename the raw Cargo binary. Windows CI builds
  the shell and checks the exact filename consumed by release packaging.
- **`frontendDist: ../dist`**: the Vite multi-page build emits
  `dist/index.html` + `dist/editor.html` (verified on Linux), matching the
  `main`/`editor` window URLs. `src/*.html` was moved to the package root
  (standard Vite layout), which also fixes `npm run dev` under `devUrl`.
- **Initial windows move to Rust `setup`**: `tauri.conf.json` keeps
  `windows: []`; launcher mode builds `main`, `--config-editor` builds only
  `editor`. This keeps dashboard init (migration + service autostart) from
  ever running in standalone mode. Editor shutdown runs
  `Running → Closing → ReadyToExit` (drained → exit 0, deadline → exit 1);
  edit sessions hold a per-config-dir OS-managed lock; `--config-dir`
  requires `--config-editor`; saves use a per-process unique tmp + atomic
  rename.
- **Wrapper `.env` autoload**: standalone `wrapper.exe` reads
  `<config-dir>/.env` (CLI > env > file > defaults, empty env wins over
  the file, invalid ports fail startup). Decode/parse lives in the shared
  `shogihome-env-file` crate reused by the launcher; the launcher passes
  `--no-env-file` with its resolved snapshot.
- **`editor_probe` is async**: Tauri runs non-async commands on the main
  thread, and a probe can take seconds, so the command now wraps the
  blocking probe in `spawn_blocking`. Cancellation via the shared flag is
  unchanged. First Windows build verifies compilation (Linux cannot build
  `src-tauri`).
- **Icons are committed** (`src-tauri/icons/`, generated by
  `tauri icon` from `shogihome/build/icon.png`); `tauri build` fails
  without them.

## 3. License pipeline (validates on Linux)

- Rust: `about.toml` license gate + `scripts/generate_rust_licenses.py`
  (`cargo about --format json` → text). Verified: 94 workspace crates,
  gate passes with `CDLA-Permissive-2.0` accepted for `webpki-roots`
  (Mozilla CA list, permissive data license, notices preserved).
- Launcher UI: pinned `license-checker` (same major as `shogihome`).
- Server/browser: unchanged (`npm run license` inside `shogihome` build).
- `cargo-about` is pinned to 0.9.2 in `release.yml` (same version used
  for local validation).

## 4. Artifact validation (no repo files)

`release.yml` boots the assembled tree with CWD outside the repo and
speaks the wrapper contract over TCP: manifest check (exes, server
bundle, webapp, both `.env` seeds, `engines.json`, `VERSION`, both
license files non-empty) plus `list` against an empty registry expecting
`[]`. This catches the `server_settings.py` class of defect
(`phase-0-baseline.md` §4). The launcher GUI itself is manual acceptance
(§8).

## 5. Startup / memory (Linux dev machine, 2026-09-13)

`cargo build --release -p shogihome-engine-wrapper` → 1.66 MB binary.
Rerun: `uv run python engine-wrapper/scripts/measure_phase0_baseline.py`.

| Impl | Time to listen | Wrapper RSS alone (0.5s after ready) |
|---|---|---|
| Python | 0.052s | ~25 MB |
| Node | 0.051s | ~54 MB |
| Rust (release) | 0.051s | ~4.1 MB |

Listen latency is TCP-bound and identical, as predicted in
`phase-0-baseline.md` §3. The rewrite's win is memory (~6–13× smaller
resident wrapper) and removing the embedded-Python/Tk/.NET chain for the
launcher. Launcher + service-ready path, Windows release numbers, and
per-component reporting stay open until §8 runs.

## 6. CI (`test.yml`)

- `test`: + version-authority step (system python3, stdlib).
- `test-rust`: fmt, clippy (`-D warnings`), `cargo test --workspace`,
  contract suite with `WRAPPER_CMD=rust` (auto-builds debug binary).
- `test-launcher-ui`: `tsc --noEmit`, `vitest`, production `vite build`
  (guards `frontendDist` drift and window URL mismatches).
- `test-python` unchanged (legacy fallback stays green).
- `test-launcher-windows`: service lifecycle and inherited-pipe regressions,
  Rust wrapper contract (including `.cmd` launchers), and a Tauri no-bundle
  build with an assertion on the portable executable's filename.

## 7. Old implementations

`engine_wrapper.py`, `engine-wrapper.mjs`, `shutdown-coordinator.mjs`,
`launcher.py`, `config_editor.py`, and supporting modules stay in the
repo and in CI. Rationale: the first Rust-based release ships as a draft
with manual acceptance (§8); deleting the fallback before that release
proves itself removes the only working rollback. Removal is a separate
change after one successful release, not part of this cutover.

## 8. Windows acceptance (not runnable here)

First Windows build surfaced three errors (Linux cannot build
`src-tauri`), all fixed on the branch:

- `tauri::tray` needs the `tray-icon` Cargo feature (`features = []`
  leaves the module configured out). The tray also gets an explicit
  icon (bundled app icon, 1×1 fallback) since Windows requires one.
- Tauri commands need `Serialize` on custom return types:
  `UpdateInfo` gained `serde::Serialize` plus a serialization test.
- `Window::app_handle()` returns `&AppHandle`; the editor-close probe
  cancel now clones it. Unused `Duration` import / `handle` removed.
